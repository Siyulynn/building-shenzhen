# Historical evidence protocol
**Version 0.1.** This protocol applies to every historical fact that reaches the game. That includes figures, dates, events, documents, maps, aerial and satellite imagery, GIS datasets and photographs.

The rule behind everything here: **nothing reaches the game because someone remembers it, including an AI.** Every fact goes back, through a recorded chain, to a source that someone opened, at a specific place in it, and a person signed it off.

---

## 1. Principles
1. **Evidence, interpretation and game values are kept apart.**
   - A *claim* records what a source says.
   - An *assessment* records what we conclude about that claim.
   - A *parameter* or *start-save value* records what the game uses.

   Each one links back to the one before it.
2. **Official does not mean correct.** Yearbooks are revised, definitions change, and figures from different statistical vintages conflict. We record which vintage and definition each figure follows, so we know exactly what it is.
3. **Keep every version.** When sources disagree, we keep all of them and record which one we chose for which use, and why. We never quietly average or overwrite.
4. **Record reuse rights at intake.** Every source gets its reuse terms when it is first captured, not at release time.
5. **Every processing step can be re-run.** A script and a log record how each raw file became a claim or a GIS layer.
6. **AI finds and extracts; people verify.** AI output is a *lead* or a *candidate extraction*, never a verified fact (§8).

---

## 2. The objects

| Object | What it is | Where it lives |
|---|---|---|
| **Source** | One document, dataset, image, map sheet or photograph, with its metadata and a copy of the file | `data/evidence/sources/<source_id>.yaml`, with raw files in `data/raw/sources/<source_id>/` (git-ignored, recorded by hash) |
| **Claim** | One atomic assertion read from a source at an exact place (a locator). For example: "end-2009 resident population = 891.23万, 2011 housing plan, §1" | `data/evidence/claims/<topic>/*.yaml` |
| **Observation** | A spatial claim: a feature with a geometry, observed at a date, with a status (proposed, under construction, completed, demolished) | `data/evidence/observations/<layer>/*.geojson` plus a metadata sidecar |
| **Assessment** | A verification verdict on a claim or observation: by whom, when, how, and with what result | Inside the claim record (`assessments:` list) |
| **Conflict** | A set of claims that disagree, plus the resolution chosen for each use | `data/evidence/conflicts/*.yaml` |
| **Derived value** | A number computed from claims, with its formula, such as a growth rate or a per-capita value | `data/evidence/derived/*.yaml` |
| **Usage link** | Where a claim is used: event IDs, target series, start saves, parameters, encyclopedia entries | Generated by the compiler (§9) |

IDs are stable and never reused. A source ID looks like `sz_gov_2011_housing_plan`. A claim ID looks like `pop.resident.2009.sz_gov_2011_housing_plan`.

## 3. Source tiers
The tier describes **where a source comes from**. It says nothing about whether the source is true. A tier-A figure can still be revised or contradicted.

| Tier | Kind | Examples |
|---|---|---|
| **A** | Official primary documents | Government gazettes (政府公报), statistical yearbooks and communiqués, laws and State Council decisions, budget reports, official planning documents |
| **B** | Contemporaneous primary material, not official | Period newspapers, company reports, dated archival photographs, archival aerial and satellite imagery, survey maps |
| **C** | Scholarly secondary sources | Peer-reviewed papers, academic books, World Bank and similar studies that cite their sources |
| **D** | Journalistic and retrospective secondary sources | Anniversary features, blogs by researchers, encyclopedia articles |
| **E** | Leads only | Search-result summaries, AI output, reviews by other models, memory, unsourced web pages. **Never sufficient on its own** |

## 4. Status lifecycle

```
lead ──► sourced ──► verified
  │         │  ╲
  │         │   ╲──► disputed ──► (resolved per use) ──► verified-for-use
  └─────────┴──────► rejected
                     superseded (a newer vintage or a better source replaces it)
```

| Status | Meaning | Who can set it |
|---|---|---|
| `lead` | Someone asserted it, but nobody has opened a source yet. Typical origins: memory, AI, an outside review, a search summary | Anyone, including AI |
| `sourced` | A source was opened. The exact locator and a short quote are captured, and the value was transcribed in its original units | AI or a person. AI extractions are tagged `extracted_by: ai` |
| `verified` | It passed the checks for its type (§5), and a person signed it off | **People only** |
| `disputed` | Sources at the same or better tier disagree. A conflict record exists | Anyone |
| `rejected` | The source does not support it, or it was misattributed | People only |
| `superseded` | A newer vintage or a better source replaces it. The old claim is kept | People only |

**Minimum status for each use** (the strict compiler enforces these; the draft compiler only tags what falls short, §9):

| Use | Minimum |
|---|---|
| Calibration target series | `verified` |
| Date of a national anchor or local milestone | `verified` |
| Fiscal regime rules (tax shares and similar) | `verified` |
| Geometry in a start save | `sourced`, with a confidence value, and shown with that confidence |
| A building on a walkable route | `verified` against at least one dated photograph or plan |
| Encyclopedia text | `sourced`, with citations shown. `lead` is never allowed |
| Vignettes and flavour text | `sourced` for every factual detail. Invented characters are fine when labelled as fiction |
| Balance parameters | No minimum, but the parameter file must point to the claims that informed it, if any |

## 5. Procedures by evidence type

### 5.1 Statistical figures
- **Capture:**
  - the table ID or page and the row and column;
  - the value **exactly as printed**, in its original unit (万人, 亿元, 万元);
  - the parsed number;
  - the unit conversion, written out explicitly.
- **Context fields (required):**
  - `definition`, for example 常住 or 户籍, constant or current prices;
  - `vintage`: the publication year, and whether the figure was revised after a census;
  - `geography`: citywide (全市) or municipal level (市级), inside the line, or a named district;
  - `reference_period`: year-end, annual average, or a census date such as 2010-11-01.
- **Checks:**
  1. **Second transcription:** re-read the value independently. If it was extracted from a PDF or by OCR, check it against the page image.
  2. **Internal consistency:** components add up to totals, the implied ratios and per-capita values are plausible, and growth rates match the published growth rate (within rounding).
  3. **Cross-vintage check:** look for the same item in other vintages. If the values differ, open a conflict record (§6).
- **Verified when:** it is tier A, or tier C with a traceable citation, and checks 1 and 2 pass, with a person's sign-off.

### 5.2 Events and dates
- **Capture:**
  - the date and its precision (`day`, `month`, `year`, `circa`);
  - what happened, who acted and where;
  - a short quote of no more than 30 characters or words;
  - the locator in the source.
- **Checks:** make sure the source dates the event itself and is not just dating its own report. Watch for a decision date, a publication date and an effective date being mixed up. The State Council tax-sharing decision is a good example: dated 1993-12-15, effective 1994-01-01, published in the Shenzhen gazette 1994-01-31.
- **Verified when:** there is one tier-A or tier-B source, or two independent tier-C or tier-D sources that agree, and a person signs off.

### 5.3 Reports and official documents
- **Capture:** the title, the issuing body, the document number (文号), the signing date and the publication date. Save a local copy and record its SHA-256 hash and retrieval date. The live URL is not enough, because government sites move pages.
- **For scanned PDFs:** keep the page images. Run Chinese OCR, then proofread every passage you actually extract from against the image.
- **For PDFs with unusual fonts:** text extraction can fail silently (for example on the `Adobe-GB1` character collection). If a check finds "nothing", confirm that the text was actually readable before recording `DOES NOT MENTION`.

### 5.4 Maps and plans
- **Capture:**
  - the title;
  - the survey date and the publication date, which are often different;
  - the scale and the original projection;
  - the issuing body;
  - the **map status**: `survey` (what existed), `plan` (what was proposed) or `schematic`.
- **Georeferencing:**
  - Use at least 6 well-spread ground control points (GCPs) on stable features.
  - Record the transform and its RMS error in metres.
  - Store the GCP file next to the map.
- **Digitising:**
  - Trace one feature class per layer.
  - Every feature carries `observed_date`, `status`, `source_id` and `confidence`.
  - Features from a plan are stored as `proposed`, never as `completed`.

### 5.5 Aerial and satellite imagery
- **Capture:**
  - acquisition date;
  - sensor or camera, and resolution;
  - provider and scene or frame ID;
  - cloud cover;
  - processing level;
  - reuse terms.
- **Orthorectification and alignment:** register every image to a common WGS84 base, and record the residual error.
- **Interpretation:**
  - Classify land use from the imagery, keeping an interpretation key with example chips for each class.
  - Run an accuracy check on random sample points that a person labels.
  - Record the confusion matrix with each derived layer.
- **What imagery can and cannot show:** built-over (impervious) datasets date *expansion*, but they miss *redevelopment* on land that was already built over. Redevelopment needs other evidence: maps, photographs and documents.

### 5.6 GIS datasets
- **Capture:**
  - dataset name, version and DOI;
  - licence;
  - resolution and the stated accuracy;
  - the coordinate system;
  - the processing steps, as scripts in `pipeline/`.
- **Coordinate warning:** Chinese commercial web maps use offset coordinate systems (GCJ-02 or BD-09). Never mix them with WGS84 data, and never scrape commercial Chinese map services.
- **OpenStreetMap (ODbL):** keep any database derived from it separate. It carries attribution and share-alike obligations.

### 5.7 Photographs
- **Capture:**
  - the date and how it was established: caption, archive record, or dating evidence such as signage, vehicles, buildings that are known to have been built or demolished, or clothing;
  - its precision;
  - the location, and for walkable routes the **camera position and direction**;
  - photographer or rights holder;
  - archive reference;
  - reuse terms.
- **Rights:** the default is `reference_only`. A photo may inform modelling, but it can't be shown in the game without a licence that has been recorded.
- **Route verification:** a route building is `verified` when its massing, openings and signage positions match at least one dated photograph or plan from the period it represents.

## 6. Conflicts and vintages
When two claims about the same thing disagree:
1. Open a conflict record that lists every claim, with their definitions, vintages and geographies.
2. Decide whether they really are about the same thing. They often aren't: different definitions, a different geography, or a figure from before or after a census revision.
3. Record a **resolution for each use**. One series might be canonical for calibration, and another shown in the encyclopedia as context.
4. Never average. Never drop a value without recording that.

**Worked example (a real case):**
```yaml
id: conflict.pop.resident.2009
subject: Shenzhen resident population, end-2009
claims:
  - pop.resident.2009.sz_gov_2011_housing_plan   # 891.23万, sourced 2026-11-22, verify pending sign-off
  - pop.resident.2009.yearbook_2014              # 995.01万, lead (cited by an outside review; not yet opened)
diagnosis: probable vintage difference (pre- vs post-2010-census revision)
resolution:
  calibration: use one consistent vintage for the whole 1979-2009 series (decision pending)
  encyclopedia: show both, with an explanation of the revision
status: open
```

## 7. Licensing and reuse classes
These are recorded on every source at intake.

| Class | What the game may do |
|---|---|
| `public_domain` | Use and display, with a credit where it is customary |
| `open_attribution` (CC BY and similar) | Use and display, with attribution |
| `open_share_alike` (ODbL, CC BY-SA) | Use, but derived databases carry the same licence |
| `reference_only` | Inform modelling and research. **Never** display or redistribute |
| `licensed` | Display under the recorded terms. Store the licence document |
| `unknown` | Treat as `reference_only` until the terms are cleared |

Short quotes in claim records are for verification only. Encyclopedia text is written fresh, not copied.

## 8. How AI is used

**Allowed:**
- finding candidate sources;
- running OCR and translating;
- extracting *candidate* claims with exact locators and quotes;
- running consistency checks;
- detecting conflicts;
- drafting conflict diagnoses;
- georeferencing first drafts.

**Not allowed:**
- recording a value without a locator;
- setting `verified`, `rejected` or `superseded`;
- inventing or paraphrasing quotes as if they were verbatim;
- recording "the source doesn't mention X" when the source wasn't actually readable.

**The standard prompt for checking a source** (the one used in the November 2026 checking pass):
> Fetch the page. For each claim, report **SUPPORTS / CONTRADICTS / DOES NOT MENTION**, with the exact quote in the original language (keep it short), your translation, and the locator. Give the page's real title, issuer and date. If the page could not be read, say so; don't guess.

Every claim an AI extracts gets `extracted_by: ai` and the name of the model or agent. It stays `sourced` until a person signs it off.

## 9. Pipeline and tooling
```
intake ──► extract ──► validate ──► verify (human) ──► compile ──► game data
  │           │            │               │                │
sources/   claims/      schema,         sign-off log     targets CSVs, fiscal regimes,
raw files  observations units, ranges,  in assessments   event dates, start saves,
+ hashes   (+ ai tag)   consistency,                     encyclopedia citations,
                        conflicts                        usage links
```
- **Commands to build:**
  - `evidence:intake <url|file>` creates the source record, stores the file and records its hash;
  - `evidence:validate` runs schema, unit, range and consistency checks and conflict detection;
  - `evidence:status` produces a dashboard of counts by status, coverage by era and area, the oldest open leads, and claims blocking a compile;
  - `evidence:compile` produces the game-facing files, and **fails** whenever a use gets less than its minimum status (§4);
  - `evidence:compile --draft`, the default in Phases 0–2, lets `lead` and `sourced` claims through, with an `[UNVERIFIED]` tag on every value, card and encyclopedia line that uses them. Draft output is flagged in the save header. Historical mode, calibration reports and release builds refuse it. Strict mode starts with Phase 3.
- **Build the tooling in stages:** a schema validator and draft compile in Phase 0; intake with hashed copies, status and strict compile in Phase 3. Archival sign-off must never block gameplay work.
- **Spatial work** happens in QGIS and in Python scripts under `pipeline/`. Every exported layer has a metadata sidecar.
- **Verification sessions:** a regular human session works through the `sourced` queue and signs claims off. Each sign-off records the reviewer, the date and the method.

## 10. Record templates

**Source:**
```yaml
id: sz_gov_1995_budget_report_1994
title: 深圳市1994年预算执行情况和1995年预算（草案）的报告
issuer: 深圳市财政局 (delivered by the bureau director to the 2nd Municipal People's Congress, 1st session)
doc_date: 1995-05-18
published: { where: 深圳市人民政府公报 1995年第11期（总第71期）, date: 1995-06-15 }
url: https://www.sz.gov.cn/zfgb/1995/gb71/content/post_10056253.html
retrieved: 2026-11-22
local_copy: { path: data/raw/sources/sz_gov_1995_budget_report_1994/page.html, sha256: <fill on intake> }
tier: A
language: zh-Hans
reuse: public_domain   # check: official documents; confirm before display
```

**Claim (a figure):**
```yaml
id: fiscal.basic_construction_share.1994.municipal
source: sz_gov_1995_budget_report_1994
locator: section on 1994 expenditure, 基本建设支出 paragraph
quote: "占市级财政支出的35.5%"
value_raw: "35.5%"
value: 0.355
definition: basic construction expenditure / municipal-level (市级) budgetary expenditure
geography: municipal level
reference_period: 1994
status: sourced
extracted_by: ai:web-fetch-agent
assessments: []
```

**Claim (an event):**
```yaml
id: event.tax_sharing_decision
source: sz_gov_gazette_1994_01_state_council_tax_sharing
date: { decision: 1993-12-15, effective: 1994-01-01, published_locally: 1994-01-31, precision: day }
summary: State Council introduces the tax-sharing fiscal system
quote: "增值税中央分享75%，地方分享25%"
status: sourced
```

**Observation (a map feature):**
```yaml
# sidecar for data/evidence/observations/buildings/yumin_1984.geojson
layer: buildings
source: <map or photo source id>
observed_date: { value: 1984, precision: year, basis: survey date on sheet }
status_of_features: completed
georef: { gcps: yumin_1984.points, rms_m: 3.2 }
confidence: 0.6
reuse: reference_only
```

## 11. Open questions
- Whether one statistical vintage is used for the whole 1979–2009 calibration series, or a spliced series with a documented break.
- Whether a dedicated person (or a second reader) is available for sign-off, or whether this is solo self-review with a cooling-off delay.
- Which archives to approach for photograph licences: municipal archives, newspapers, private collections.
