## Investigation results

### The leader's shortcut fires once per pending offer, not once per turn

`packages/sim-core/src/investors.ts` walks **every** pending investor card without a zone site:

1. `shortcutOffered` stops the same offer raising a second shortcut.
2. It does not stop *sibling* offers raising their own shortcut in the same tick.
3. At the first wave, two processing contracts plus other offers produced four identical `leader.shortcut` cards. The shortcut payloads differ (`offerCard`, `offer`, `leader`), but the card title and options are identical, so the queue looks like four copies.

**Conclusion:** the shortcut is deterministic, not random. The trigger is correct; the multiplicity is the problem.

**Proposed rule:** keep at most **one pending shortcut card at a time**. While a shortcut is pending, skip the shortcut loop. This needs no new saved state: `s.pendingCards.some((c) => c.card === SHORTCUT_CARD)` is enough. The shortcut card must also name the offer it belongs to (archetype and jobs).

**Golden impact:** yes. The number and timing of shortcut cards change. Regenerate the goldens and record the difference in the tuning log.

### An offer with only “Decline” is still raised

`siteOptions()` returns `['decline']` when no zone fits and no premises fit. `raiseOffer()` still raises the card. The playtest saw “Inland state unit” and “Overseas Chinese firm” with only Decline.

**Proposed rule:** do not raise an offer card whose options are only `decline`. Log `offer_not_sited` with the reason (no serviced zone / premises full / origin locked). If we want the player to see it, show one compact “Offers without a site: N” line in the decisions footer, not a dead card.

**Golden impact:** yes. Regenerate and explain.

### The readiness drop was power demand, not a formed-land bug

Measured on the start state and the first quarter:

| Part | Start | After first quarter |
|---|---:|---:|
| Roads | 0.0% | 0.0% |
| Formed land | 0.0% | 7.0% |
| Water and power | 37.5% | 18.8% |
| Bar | 13.1% | 9.0% |

`readiness()` is correct: formed land rose from zero to 7%; the bar fell because three new firms consumed the spare power, cutting the water/power part by 18.7 points. The UI simply never says this.

**Proposed rule:** keep the formula; add “since last quarter” deltas and a causal line:
*“Water and power −18.7 points: 3 new firms connected; formed land +7.0.”*

Add a regression test for this exact start-to-first-quarter movement.

### The 1984 historical plan is extractable

`docs/spikes/scene-review/zoning/index.html` is a proposal viewer for two maps. Its data is in `core-basin-proposals.json`, and the drawn cells are in `core-basin-1984.svg`.

The SVG is directly usable:

- each zone is a `<g><title>Name · use, intensity, stage · N cells</title><path class="use intensity" d="M x,y h12v12 …"/>`;
- one SVG cell is 12×12 pixels;
- the proposal box is `[344, 343, 419, 398]` on the game grid, so:
  `gameX = 344 + floor(svgX / 12)`, `gameY = 343 + floor(svgY / 12)`.

This gives the 1984 proposal zones (Shangbu factories/housing, Luohu frontage/commercial/housing, Bagualing, Shuibei, Hubei, Huangbeiling, Shangbu reserve) without touching the two existing precedents.

`atlas_zones` references in the JSON are not resolvable from the repo, but the SVG paths are. The extracted file should be a **design proposal reference**, not an evidence claim: keep the proposal’s own claim ids, mark the layer `design_note`, and never let it create orders.

## Batch C — works, roads and cost feedback

**Problem:** a one-cell drag error produced a road and formation orders stuck on “no road access”; Cancel looked like it did nothing; the city had 850 crews but each order used 40; costs did not show compensation.

### C1 — UI feedback and cost breakdown

- **Cancel pending:** when a `cancel_works` action for an order is in `x.queue`, mark the order **“Cancel pending”**, disable further Cancel clicks, and keep the original order visible only as “will be removed at quarter end”.
- **Missing link:** in the works card, show the nearest connected road cell and the gap; add **“Show gap”** which centres the map on the end of the disconnected order.
- **Continue road:** add a UI action that selects Roads, centres on the gap and starts the next drag from the disconnected end. The planner still asks the player to drag.
- **Priority:** show **“High priority”** on orders and in the queue after “Rush the works”; do not silently change the card.
- **Crew cap:** show the per-order cap next to the crew figure (“40 crews per order; 850 total”).
- **Cost:** show **compensation** and the **per-class split** in the works queue and the order preview, not only the total. The 8-cell farmland case was ¥528k, of which ~¥240k was compensation.
- **Overspend:** state the rule. Prefer a visible warning on the budget chip and in the stack: “¥76,636 over available; the quarter will draw on the next grant / reserve” or a hard refusal. Do not leave the player guessing.

### C2 - per-order crew allocation (implemented)

`WorksOrder.crew?: number` is the order's monthly allocation; absent means `works.crew_per_order`. `set_works_crews { order, crews }` accepts a whole number from 1 to `10 × crew_per_order`, and calling it with the default removes the field. The allocation is used by both the materials budget and the monthly pool draw, so the city's total pool, the area's materials and the money still cap the order. The Building drawer offers 1×, 2×, 3× and 4× the default.

This is deliberately a per-order lever, not a global cap change: concentrating crews can starve other orders. No save version bump is needed because the field is optional and absent means the default.

**Acceptance**

- Cancel is visibly pending; the order cannot be cancelled twice.
- A disconnected order shows a gap and a one-click way to centre on it.
- “Rush” leaves a visible high-priority marker.
- The works queue explains the crew cap and the compensation.
- The overspend rule is stated in the UI and enforced or explained.
- C2 has a documented design decision and a test for the chosen behaviour.

**Tests**

- `r11_2.test.ts`: cancel pending, gap, priority, compensation row, overspend warning.
- If C2 changes tools/actions: a queue test and golden update.

## Cross-batch rules

- **Determinism:** no wall-clock, no unseeded RNG; every preview stays pure.
- **Dates in content:** no balance code branches on a year. The 1984 plan lives in content/data with its claims.
- **Bilingual:** any new string or place label is `{zh, en}`; place labels stay bilingual in both languages.
- **Goldens:** only Batch A, G1 and any C2 balance change should move them. Explain the movement in `docs/design/m6-tuning-log.md` and keep the diff reviewable.
- **No scope drift:** no 3D, no archival tooling, no building serializer. The historical plan parser is a small game-reference pipeline, not an archive.
- **One system per session:** A1 sim, A2 UI, B UI, C1 UI, D UI, E UI, F data, G content. Do not mix a sim change with a map redesign in one commit.
